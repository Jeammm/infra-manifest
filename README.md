# infra-manifest

Production-grade GitOps control plane for a k3s home lab server, powered by ArgoCD and Cloudflare Tunnel.

## Architecture

```
                  Internet
                     │
              Cloudflare Edge
              (TLS termination)
                     │
            ┌────────┴────────┐
            │  cloudflared    │  ← managed by the ingress controller
            │  (2 replicas)   │
            └────────┬────────┘
                     │
        ┌────────────┼────────────┐
        ▼            ▼            ▼
   ArgoCD UI    whoami app   guestbook app
   (argocd)     (whoami)     (guestbook)
```

**Components:**
- **k3s** — lightweight Kubernetes (Traefik disabled)
- **ArgoCD** — GitOps continuous delivery, syncs this repo
- **Cloudflare Tunnel Ingress Controller** — watches Kubernetes Ingress resources and automatically creates tunnels, DNS records, and routes
- **Sealed Secrets** — encrypt secrets in Git safely

## Prerequisites

- A Linux server (Ubuntu/Debian recommended, x86_64 or arm64)
- A Cloudflare account with a domain
- A Cloudflare API token with permissions:
  - **Account** → Cloudflare Tunnel → Edit
  - **Zone** → DNS → Edit

## Quick Start

### 1. Clone and configure

```bash
git clone https://github.com/Jeammm/infra-manifest.git
cd infra-manifest
cp scripts/.env.cloudflare.example scripts/.env.cloudflare
```

Edit `scripts/.env.cloudflare` with your Cloudflare credentials:

```env
CF_API_TOKEN=your-api-token
CF_ACCOUNT_ID=your-account-id
CF_TUNNEL_NAME=k3s-homelab
CF_DOMAIN=yourdomain.com
CF_ZONE_ID=your-zone-id
```

### 2. Run the installer

```bash
sudo bash scripts/install.sh
```

The installer will:
1. Install k3s (Traefik disabled)
2. Install Helm
3. Install ArgoCD and configure insecure mode (TLS at Cloudflare edge)
4. Install Sealed Secrets controller + kubeseal CLI
5. Generate a SealedSecret with your Cloudflare credentials
6. Apply the ArgoCD root application

The ingress controller then automatically:
- Creates a Cloudflare Tunnel
- Registers DNS CNAME records for each Ingress hostname
- Routes traffic to the correct cluster services

### 3. Commit generated files

```bash
git add manifests/cloudflare-tunnel/sealed-secret.yaml
git commit -m "Add Cloudflare tunnel credentials"
git push origin main
```

### 4. Access your services

| Service    | URL                                |
|------------|------------------------------------|
| ArgoCD UI  | `https://argocd.yourdomain.com`    |
| whoami     | `https://whoami.yourdomain.com`    |
| guestbook  | `https://guestbook.yourdomain.com` |

ArgoCD credentials:
```bash
# Username: admin
# Password:
kubectl -n argocd get secret argocd-initial-admin-secret -o jsonpath='{.data.password}' | base64 -d
```

## How It Works

### App-of-Apps Pattern

The `bootstrap/root-app.yaml` is a single ArgoCD Application that watches the `apps/` directory. Every YAML file in `apps/` defines another ArgoCD Application. ArgoCD recursively syncs them all.

```
root-app (syncs apps/)
 ├── sealed-secrets     → Helm chart (kube-system)
 ├── argocd-config      → manifests/argocd/
 ├── cloudflare-tunnel  → manifests/cloudflare-tunnel/
 ├── whoami             → manifests/apps/whoami/
 └── guestbook          → external: argoproj/argocd-example-apps + ingress
```

### Sync Waves

Infrastructure components use sync waves to ensure correct ordering:

| Wave | Application       | Purpose                          |
|------|-------------------|----------------------------------|
| -3   | sealed-secrets    | Must exist before SealedSecrets  |
| -2   | argocd-config     | Server config before tunnel      |
| -1   | cloudflare-tunnel | Depends on sealed-secrets        |
| 0    | whoami, guestbook | Regular apps (default)           |

### Cloudflare Tunnel Ingress Controller

The controller watches Kubernetes `Ingress` resources with `ingressClassName: cloudflare-tunnel` and **automatically**:
- Creates and manages the Cloudflare Tunnel
- Registers DNS CNAME records for each hostname
- Configures tunnel ingress routes
- Spawns `cloudflared` connector pods (2 replicas for self-healing)

This means adding a new service requires **zero manual Cloudflare configuration** — just create an Ingress resource and the controller handles the rest.

### Sealed Secrets

Secrets are encrypted with the cluster's Sealed Secrets public key and stored safely in Git. Only the Sealed Secrets controller in the cluster can decrypt them.

The install script handles sealing automatically. To seal additional secrets manually:

```bash
kubectl create secret generic my-secret \
    --namespace my-ns \
    --from-literal=key=value \
    --dry-run=client -o yaml \
| kubeseal --format yaml \
    --controller-name sealed-secrets \
    --controller-namespace kube-system \
> manifests/path/to/sealed-secret.yaml
```

## Adding a New Service

1. **Create manifests** in `manifests/apps/myapp/` (Deployment, Service, Ingress):

   ```yaml
   # ingress.yaml — this is all the controller needs
   apiVersion: networking.k8s.io/v1
   kind: Ingress
   metadata:
     name: myapp
     namespace: myapp
   spec:
     ingressClassName: cloudflare-tunnel
     rules:
       - host: myapp.yourdomain.com
         http:
           paths:
             - path: /
               pathType: Prefix
               backend:
                 service:
                   name: myapp
                   port:
                     number: 80
   ```

2. **Add an ArgoCD Application** in `apps/myapp.yaml`:

   ```yaml
   apiVersion: argoproj.io/v1alpha1
   kind: Application
   metadata:
     name: myapp
     namespace: argocd
   spec:
     project: default
     source:
       repoURL: https://github.com/Jeammm/infra-manifest.git
       path: manifests/apps/myapp
       targetRevision: main
     destination:
       server: https://kubernetes.default.svc
       namespace: myapp
     syncPolicy:
       automated:
         prune: true
         selfHeal: true
       syncOptions:
         - CreateNamespace=true
   ```

3. **Commit and push** — the controller automatically creates the DNS record and tunnel route. No Cloudflare dashboard needed.

## Teardown

Remove all workloads and ArgoCD (keeps k3s):
```bash
sudo bash scripts/teardown.sh
```

Full reset (removes everything including k3s):
```bash
sudo bash scripts/full-reset.sh
```

Both scripts also clean up the Cloudflare tunnel and DNS records via API.
